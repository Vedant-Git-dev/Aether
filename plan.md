## Threat model and locked decisions

* A copied database plus copied serving-host configuration must give no offline decryption path and no working panel login. Test the combination against a running honest service. A request signature by itself cannot redirect the phone’s reply, create an outstanding server task or obtain plaintext from an API. A server configuration leak can still compromise external services whose transport credentials it contains; inventory these separately.
* Treat plaintext user content, filenames, identifiers, contact handles, provider credentials, prompts, vectors, model outputs and low-entropy public hashes of them as sensitive. A dump/backup/export/log must disclose none of them. The schema necessarily exposes ciphertext lengths/counts, access timing, versions, coarse categories and public protocol metadata. Disclose this residual metadata and obtain agreement at G0. Encrypt device access logs, backups and workspace markdown. Include spool files, browser cache, OS backups and error telemetry.
* The trusted running backend sees authorized data while leased. A compromised live process, malicious dependency and active takeover of the owner’s serving and database accounts are outside scope. Model providers, messengers, connector endpoints and configured workbench processors can see the content sent to them. Name recipients and retention limits in docs. A lock cannot recall delivered data or undo a committed action.
* Prevent web/API bugs from exposing plaintext through unauthenticated or cross-scope reads: put authorization and typed projection **below** route handlers, deny direct decrypt handles to UI, bind destination/owner/task, test raw error paths and late responses. Arbitrary code execution in this process crosses the stated trust boundary. A bug or script in an already authorized view can see its displayed values. If protection against that case is required, stop: decrypt/display on a separately trusted client is a different architecture.
* Prompt injection is untrusted input. Authorize egress by the actual bytes/destination and provenance, including URL/query/header/tool args, model context, file upload, browser redirects, shell/workbench and messenger fanout. A model with private context cannot initiate arbitrary network calls. Carry a conservative label for the **whole** turn and all descendants, even after summarization. Only send to a trusted owner surface or explicitly configured processor for that scope. New external disclosure requires deterministic confirmation of immutable destination and exact payload digest from a trusted owner surface. No model-made approval or automatic declassification. Include context isolation for other chats and identities.
* Keep one production mode. No server fallback key, software release vault, dual-read forever, feature flags, raw JSON in UI, new token caps or connector message trimming. Put defaults in validated configuration/data, wire constants in a versioned schema, text in the catalog and word lists in library resources. Fixtures/fakes only in tests or dev tooling. Only signed packaged UI runs on phone; no browser vault.
* RAM lifetime includes every derived plaintext object, not just DEKs. Protected native memory for cryptographic keys, short-lived task contexts for plaintext, cancellation/fencing at each read, send and commit. CPython cannot promise zeroization of arbitrary objects. Protected native memory holds cryptographic keys; a managed-heap cleanup cannot substantiate forensic-erasure claims.

## Verification and evidence

1. **Protocol and lifecycle.** Use a controllable clock, fake push, tests-only software vault, real HTTP transport, scratch Postgres, and two fresh server boots. Run pair → public-only boot → queue event+attachment → partial grant → short-task completion and immediate release → long-task automatic refresh → orphan expiry → replay → lock → restore. Interleave task finish, lock, late grant, HTTP cancellation and DB commit. Assert no side effects after invalidation and no lock or push action requires loading React. Test duplicated nonce across request IDs, tampered wrap, bad signature, skew in both directions, duplicate grants, category escalation, stale manifest, rate exhaustion and wrong URL. Black-box a DB+config copy against the honest service.
2. **At-rest and leak tests.** Extend `tests/test_canary.py` and strict storage guard to enumerate *all* real columns and app-owned files. Seed unique markers in every category including lookup inputs, filename, attachment bytes, provider claims, callback errors, phrase/DEK test bytes, workspace name and profile. Exercise successful and failing API, model, retry, export/import, audit, logs and locked paths. Scan DB fields and logical/physical backup where available, tmp/spool, build bundle, log streams, proxy telemetry, app cache/backups, diagnostics and configuration files in a disposable environment. Scan raw, UTF-8, hex, base64/url encodings and decompressed artifacts. Test the scanner with deliberately leaky fixtures. A negative scan supplements controls; it cannot prove in-process memory handling.
3. **Ingress and policy.** Record ack point, retention limit, reconnect/cursor and credential source per supported messenger/poller. Inject crash before/after commit, partial attachment, full queue, revoked owner, out-of-order callbacks and unavailable providers. Queue replays may write one delivered outcome only; ambiguous external calls are reconciled. Test prompt injection with canaries in mail/workspace/attachments and a recording fake HTTP/MCP/LLM/workbench/messenger transport. Verify private data reaches only the approved owner/processor, including encoded values in URLs. Test failure-path catalog text and unauthorized reads for every HTTP/WS endpoint.
4. **Responsive and mobile.** Verify real keyboard resize, safe areas, back navigation, touch target dimensions, rotation, focus/zoom and all desktop actions on cards. Run plain-language E2E for locked/offline/loading/ready/revoked and background return. Inspect on-device network requests, local asset hashes, CSP, JS bridge origin, OS backups and task switcher. Record hardware/OS/target SDK and push outcomes, including a truly stopped app.
5. **Repository gates after final implementation.** Use pip and a clean checkout with only example settings. Run `ruff check src tests`, `ruff format .`, `ruff format --check .`, `python scripts/check_storage_guard.py --strict`. Create a fresh `aether_scratch_ci` in an isolated Postgres instance, set `AETHER_TEST_DATABASE_URL` to that database only and run `python -m pytest`. Build via `npm run build` in webapp, then run `AETHER_TEST_E2E=1 python -m pytest tests/e2e -q`. Drop only the scratch DB created for the test. Record counts/skips, browser/device versions and artifacts. Never use the live DB, real secrets or private configuration.
